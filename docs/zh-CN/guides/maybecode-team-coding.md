# 受控多 Agent 编码

[English](../../en/guides/maybecode-team-coding.md)

编码团队编辑的是**各任务的独立副本**，不是同一个源工作区。宿主可以把现有 `read`、`write`、`edit` 工具绑定到准备好的任务目录。模型可以在自己的副本中提出并实现改动，但不能授权合入源工作区。源文件变更需要独立的宿主命令，并提供已审阅补丁的精确摘要。

## 审查和应用

使用 `maybecode team run "在自己的副本中实现所需改动" --mode coding --workspace <path>` 显式启动编码任务。默认编码预设只给 Worker 角色开放 `write`/`edit`，Supervisor 仍然只读。自定义 `--plan <json>` 还需要为编辑角色列出对应工具；计划文件不能自行开启编码模式。

选定任务停止后，捕获它们的改动：

```powershell
maybecode team diff <team-id> --tasks worker-a,worker-b
```

命令保存不可变补丁包，显示补丁 ID、确认摘要、任务身份和 unified diff。原团队使用自定义数据目录时，需要继续使用相同的 `--data-directory`。审查完整 diff 和所有冲突标记后，再执行：

```powershell
maybecode team apply <team-id> --patch <patch-id> --confirm <exact-digest>
```

确认摘要绑定整个补丁包，包括源基线、选定任务快照、路径及改动前后的内容哈希。笼统的 `yes`、任务 ID 或旧摘要都不等于确认。不能把 apply 命令包装成模型工具，也不能让模型代替用户生成审批。

多个任务对同一路径产生完全相同的改动时，补丁会去重，并保留所有贡献任务 ID。同一路径产生不同结果时属于冲突，包括“修改与删除”冲突；不会任意选择胜者或自动合并文本。预览显示各候选改动，应用被阻止。请选择无冲突的任务集合，或在任务副本中解决冲突，再重新生成并审查补丁。

## 应用前检查

首次写入源文件内容之前，会验证：

- 补丁摘要精确匹配，且没有任务冲突。
- 不可变基线和每个选定任务快照中全部被纳入的文件仍与审查时一致。即使变化的文件不是本次要合入的文件，任务快照发生变化也需要重新生成补丁。
- 每个受影响源文件仍有基线哈希，新增路径仍不存在。所有文件都先校验，因此后面的文件发生冲突，不会导致前面的文件已被写入。
- 路径位于规范化后的源目录内。拒绝符号链接父目录、符号/硬链接文件、特殊文件、路径别名、文件/目录路径重叠、不可移植文件名，以及超限或非 UTF-8 文本。
- 可以取得每源工作区的协作式独占锁。锁位于 `~/.may/maybecode/apply-locks/`，不依赖团队 ID 或自定义数据根目录。不会自动抢占遗留锁。

任务补丁快照覆盖工作区管理器**允许纳入的源文件树**。原有隐藏文件、秘密、构建产物等排除规则仍然生效，被排除的文件不会合入。验收报告还可以绑定整个任务目录；与验收有关的文件改变后，不应复用旧的成功报告。补丁应用本身不执行测试，也不保证代码正确。

默认补丁上限为 128 条文件改动记录、每份前/后文件 256 KiB、全部前/后 UTF-8 文本共 2 MiB。不支持二进制文件、普通制表符/换行/回车以外的终端控制符，或双向显示覆盖字符。即使任务能在副本中写入被排除或超限文件，也不代表它有权限将这些文件合入源工作区。

## 部分失败和崩溃恢复

实现先持久化应用开始记录，并把全部原文件备份保存到团队的私有数据目录。每次修改源文件之前，先同步包含路径、备份、临时文件和新增目录的意图记录。新内容先写入同目录临时文件，再通过重命名替换；删除使用一次 unlink。结果文件完成 flush 和核验后，才持久化对应文件的结果。

这提供的是**逐文件替换，不是多个文件的原子事务**，也不自动回滚。应用开始后进程或日志失败时，一部分文件可能已经改变。结果为 `unknown`，列出确认已应用的路径、剩余可能受影响的路径和应用日志位置。遗留临时文件、新建目录都是证据，不是再次执行的授权。

对 `unknown` 补丁再次调用 apply 只会报告现有证据，不重放源写入。对于已有持久化完成记录的补丁，再次调用会报告已应用。出现未知结果时，需要检查源文件、备份和日志，人工核对后再创建新的审阅操作。不能仅为了重新运行 apply 就删除记录或抢占锁。

源工作区锁只协调遵守协议的 MaybeCode 应用者，无法排斥忽略该锁的编辑器或其他进程；文件副本隔离也不是操作系统沙箱。每次写入前都会重新检查源与任务文件，但调用者仍应确保选定任务已停止，并避免并发编辑源工作区。文件和日志会同步落盘；目录 fsync 会在支持时执行，并非所有 Windows 文件系统都支持。

## 宿主 API

`TaskWorkspaceManager.snapshotPatch(taskIds)` 返回有界文本改动、基线和任务摘要，不写入源文件。产品模块 `team-patches.ts` 提供：

- `createTeamPatch({ directory, workspaces, taskIds })`
- `readTeamPatch(directory, patchId)` 和 `renderTeamPatchDiff(bundle)`
- `applyTeamPatch({ directory, workspaces, patchId, confirmDigest })`
- `readTeamPatchApplication(directory, patchId)`

补丁包位于团队的 `patches/` 目录。应用记录和备份是私有宿主数据，位于任务工具目录之外，不应暴露为 Agent 可写工具。一般运行时、预算和取消行为见 [MaybeCode 团队](maybecode-team.md)。
