# 办事通知到提交

一条通知通常同时牵动邮件、办事大厅和个人资料。按下面的顺序处理，
每一步的结论都写回个人数据库，下一次同类通知可以复用。

## 1. 读通知

1. `mail_check` 找出这封新邮件，拿到 `key`。
2. `mail_thread` 读取同一往来的历史邮件，确认对方是谁、之前答应过什么。
3. 把邮件正文和关键日期写进 `projects/<事项名>.md`，用 frontmatter 标注
   `deadline`（截止时间）与 `eventAt`（活动或办理开始时间）。这两个时间必须分开写。

## 2. 找材料

1. `vault_search` 检索证件号、学号、导师、宿舍、材料模板等已有资料，命中后用
   `vault_read` 核对原文。
2. `ehall_prepare` 列出这个事务需要的材料，缺什么就写什么。
   证件照、成绩单用途这类内容写成 `records/<名称>.md`。
3. 材料齐了再往下走；缺材料时先在对话里告诉用户缺什么、需要他提供什么。

## 3. 准备表单

1. `ehall_open` 打开事务页面，`ehall_controls` 查看可填写字段。
2. 用 `ehall_fill` 按字段名称填写，值全部来自个人数据库，不要凭空编造。
3. `ehall_review` 生成字段表与字段摘要，把字段表和点击哪个按钮、提交后会发生什么
   完整告诉用户，等他确认摘要。
4. 不可撤销事务（退课、撤销申请等）到这一步为止，明确告诉用户必须由本人提交。

## 4. 起草回复

1. 结合 `mail_thread` 的往来和 `projects/<事项名>.md` 的进展，用 `mail_draft_create`
   写回复草稿。草稿只写进个人数据库，不会发出。
2. 把草稿的收件人、主题、正文给用户看；用户在网页或命令行确认之后，
   助手才能调用 `mail_send`，发送的就是被确认的那一版。

## 5. 归档

1. `ehall_submit`（可撤销事务）与 `mail_send` 分别执行，各自都会请求批准。
2. `mail_archive` 归档邮件，`ehall_archive` 归档表单字段表。
3. 在 `projects/<事项名>.md` 里写清进展、已完成的动作和待办。
4. 用户提出新的判断标准时用 `rule_learn` 记录；这套流程有改动时更新本技能。

## 注意

- 截止时间与开始时间不要混用，这是最容易出错的地方。
- 任何提交都要先展示关键字段，任何发送都要先展示完整正文。
- 办事大厅页面上的字段名以 `ehall_controls` 的返回为准，不要猜。
